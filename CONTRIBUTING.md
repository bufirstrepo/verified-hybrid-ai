# Contributing to the proposal

The project is at the design stage. Feedback should identify a concrete behavior, failure case, or measurable comparison.

Useful first contributions include:

- Reviewing the state, authority, and evidence contracts for contradictions.
- Suggesting a smaller prototype that still tests the central hypothesis.
- Designing independent grading and adversarial fixtures for code-repair tasks.
- Comparing concrete inference methods for the fusion engine.
- Assessing A2A and MCP adapter requirements for a C++ controller and a Beam-powered runtime.
- Identifying closely related implemented systems and explaining the overlap.

For a design proposal, include the problem, proposed behavior, authority boundary, failure behavior, validation method, and expected overhead. Separate evidence from conjecture.

Do not present simulated traces as real agent runs or benchmark targets as achieved results. Do not include API keys, private prompts, personal data, or proprietary task content in issues or examples.

Before substantial implementation contributions, agree on scope and repository licensing with the maintainer. No implementation language, library, model provider, or contribution license is silently assumed beyond the C++ controller in the architectural proposal.
